======================================================
PROJECT PRESENTATION & TECHNOLOGY STACK: NYAYAVAULT
======================================================

1. PROJECT OVERVIEW
------------------------------------------------------
Problem Statement ID: 26190
Title: Secure Digital Evidence & Legal Document Management
Theme: Cybersecurity & Blockchain
Team Name: NyayaVault

2. PROPOSED SOLUTION
------------------------------------------------------
NyayaVault replaces scattered storage systems with a single, secure central vault for digital evidence.
- It utilizes SHA-256 hashing and permanent activity logs to maintain provable integrity.
- Blockchain technology ensures a tamper-proof chain of custody.
- Strict JWT (JSON Web Tokens) and RBAC (Role-Based Access Control) prevent any unauthorized access.
- Integrated AI/OCR automatically extracts and indexes document contents.
- RAG (Retrieval-Augmented Generation) combined with LangChain enables smart, semantic legal search.

3. TECHNOLOGY STACK & WHERE IT IS USED
------------------------------------------------------
- **Frontend (User Interface):** Next.js + TypeScript + Tailwind CSS
  *Used for:* Building the command center, dashboards, document upload forms, and evidence registry UI.

- **Backend (Core API & Logic):** Django & Django REST Framework (Python)
  *Note:* As requested, we are using Django for the backend instead of Node.js.
  *Used for:* Managing user accounts, RBAC, API endpoints, uploading mechanisms, and orchestrating the database.

- **Database (Storage & Vector Search):** PostgreSQL + pgvector
  *Used for:* Storing relational data (users, cases, metadata) and vector embeddings for semantic AI search.

- **File Storage:** AWS S3 / MinIO
  *Used for:* Securely storing the AES-256 encrypted raw digital evidence and legal document files.

- **Blockchain (Chain of Custody):** Hyperledger Fabric
  *Used for:* Storing the SHA-256 hashes of every uploaded document and logging access events to guarantee immutability and a tamper-proof chain of custody.

- **AI & OCR (Data Extraction & Search):** Python + FastAPI + PaddleOCR + LLM + LangChain
  *Used for:* 
    1. PaddleOCR extracts text from scanned legal PDFs/images.
    2. LangChain + LLM processes the text into embeddings.
    3. RAG allows users to semantically search through thousands of case files instantly.

- **Security (Cryptography & Access):** JWT + RBAC + AES-256 + SHA-256
  *Used for:* 
    - JWT/RBAC: Securing API routes and ensuring only authorized roles (e.g., Investigators, Admins) access specific cases.
    - SHA-256: Hashing documents upon upload to verify they haven't been altered.
    - AES-256: Encrypting the physical files at rest.

- **Deployment (Infrastructure):** Docker + AWS
  *Used for:* Containerizing the Django backend, Next.js frontend, AI microservices, and PostgreSQL database for scalable cloud deployment.

4. METHODOLOGY & IMPLEMENTATION WORKFLOW
------------------------------------------------------
1. Upload: An officer uploads a document via the Next.js frontend.
2. Security: The Django backend calculates the SHA-256 hash, then encrypts the file via AES-256 before sending it to S3/MinIO.
3. Blockchain: The calculated hash and uploader metadata are logged immutably onto Hyperledger Fabric.
4. AI Processing: The AI microservice (PaddleOCR) extracts text from the document.
5. Indexing: The extracted text is passed through an LLM to generate embeddings, which are stored in PostgreSQL via pgvector.
6. Search: Users can perform smart, natural language searches (RAG) across the evidence registry.
7. Audit: Every single action (view, download, upload) is verified via JWT/RBAC and permanently recorded in the audit trail.

5. HACKATHON DEMO IMPLEMENTATION (SIMULATED FOR LOCAL PC)
------------------------------------------------------
To ensure a flawless and lightning-fast local demonstration without requiring immense cloud computing or downloading 10GB+ machine learning models, the following technologies are implemented as highly robust simulations:
- **Blockchain:** Hyperledger Fabric is simulated via a local Django ledger (`BlockchainRecord`). It generates realistic Transaction IDs and securely associates real SHA-256 hashes upon upload, proving the chain-of-custody concept.
- **AI/OCR (PaddleOCR & LangChain):** Simulated via a dedicated FastAPI microservice running on port 8001. The endpoints replicate actual processing times (using async delays) and return realistic RAG JSON responses to the frontend Intelligence Center.
- **AWS S3 Storage:** Files are encrypted with AES-256 and stored locally in a `mock-s3/` directory to demonstrate secure cryptography before hitting the disk.
